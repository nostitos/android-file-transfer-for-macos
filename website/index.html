01 / WHY

A BORING UTILITY, ON PURPOSE

This should simply exist.

Android already exposes shared storage over USB. macOS can see the hardware, but it does not ship a general MTP folder browser.

This project fills that narrow gap. It is not a phone suite, backup cloud, wireless ecosystem, or recurring service. It is a focused, inspectable bridge between two devices you own.

“This is basic device interoperability. It should be built into macOS. Until it is, this project provides it.”

“Transfer” describes four different jobs.

03 / CHOOSE

THE HONEST ANSWER

Use the smallest tool that matches the job.

Choose this project

For a cable, a visible folder tree, two-way files and folders, no Android install, no debugging, and open packaging.

Choose Quick Share / AirDrop or LocalSend

For a few wireless sends when both devices and OS versions support your preferred route.

Choose MacDroid or Phone Mechanic

When a Finder-mounted device and direct in-place editing matter most.

Choose ADB or Android Studio

When developer mode is already enabled and shell-level or app-debugging access is the point.

Choose Smart Switch or an OEM suite

For supported-device backup, migration, restore, firmware, contacts, or app-level management.

Choose Syncthing or Resilio

For continuous replicated folders over a network instead of deliberate cable browsing.

UNDER THE WINDOW

Small native edges. Explicit trust boundaries.

Electron and React present the interface. A narrow preload bridge reaches the main process, which serializes MTP work through a native helper built from pinned libmtp and libusb sources.

No independent security audit has been completed. The renderer sandbox is currently disabled, and copied diagnostics can include a device identifier and local paths. Those are documented hardening targets, not hidden caveats.

PLAIN ANSWERS

Before you plug in.

Is this the old Google Android File Transfer app?

No. It is an independent open-source project. Google’s former Mac file-transfer destination no longer distributes that browser.

Do I install anything on Android?

No. Unlock the phone and choose File Transfer, Transferring files, or MTP from its USB options.

Do I need USB debugging?

No. The app uses Android’s normal MTP shared-storage mode, not ADB.

Are files uploaded anywhere?

No. File contents move over the cable. The app has no analytics or telemetry. Its update check requests release metadata from GitHub; file contents and phone details are not sent.

Why are there two downloads?

Use arm64 for Apple-silicon Macs and x64 for Intel Macs. Each architecture is packaged and verified separately.

Is it signed and notarized?

Yes. The official v@@VERSION@@ apps and DMGs are Developer ID signed, Apple-notarized, stapled, Gatekeeper-assessed, and rechecked after upload. SHA-256 checksums are published.

Does it work with every Android phone?

Do not assume that yet. It targets standard MTP/File Transfer storage, but testing is still deepest on Samsung hardware. Broader reports are welcome.
